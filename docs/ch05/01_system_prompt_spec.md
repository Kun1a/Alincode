- F8: 跨协议一致​
  Anthropic 与 OpenAI（含兼容 base_url）都装配同一套模块化系统提示 + 环境信息、都注入相同补充消息、都尽力走缓存（Anthropic 显式断点 / OpenAI 前缀顺序）。两协议在模块内容、注入时机、规划模式注入节奏上**行为一致**；缓存命中解析在各自字段可得时生效。​
​
## 非功能需求- N1: 缓存确定性——可缓存块（工具定义 + 稳定系统模块）在跨轮、会话内多轮之间**逐字节稳定**：模块装配顺序、工具顺序固定，不混入任何随轮次/时间变化的成分。否则缓存永不命中，本章核心目标落空。​
- N2: 不破坏 ch04 行为——Agent Loop 多轮编排、流式双路收集、保序分批并发、用户取消、历史一致、用量/迭代进度展示等 ch04 能力**不退化**。系统提示重构与消息注入是叠加，不改这些既有路径的语义。​
- N3: 历史合法性——每轮动态注入的补充消息（不持久）拼进请求后，消息序列仍**角色交替合法、工具调用与结果配对不破坏**，不致 provider 返回 400；补充消息不写入持久历史，故不影响后续轮次与可恢复性。​
- N4: 环境采集不阻塞、可降级——环境信息采集（含可能外调 shell 的 git 状态）**快速且有界**，不阻塞界面、不显著拖慢请求发起；任一项取不到时降级（留空/省略），不中断会话。​
- N5: 密钥与敏感信息不泄漏——沿用 ch03/ch04，对话区与任何输出均不出现 api_key；环境信息构造**不带入密钥或敏感环境变量**。​
- N6: 缓存字段解析健壮——provider / 兼容端点未返回缓存字段时按零处理，不抛未处理异常、不因缺字段中断本轮或会话。​
- N7: 代码规范——`ruff format` / `ruff check` 合规（import 分组正确、PEP 8 一致）；可选 `mypy` 通过。​
- N8: 可扩展性——新增一类系统提示模块或一类补充消息提醒时，改动局部：不触及装配主逻辑，不改 provider 适配层对外签名的语义稳定性。​
​
## 不做的事- **项目指令文件加载**——「自定义指令」为预留空槽，本章不从 CLAUDE.md / 项目级指令文件读取内容（留待后续章节）。​
- **自动记忆 / 长期记忆**——「长期记忆」为预留空槽，本章不做记忆写入与召回。​
- **真实 MCP 接入**——「已激活 Skill」等可选模块为预留空槽，不接入 MCP 工具/资源。​
- **自动化评估 / 评测框架**——本章只做缓存字段解析验证 + 一组典型场景人工对比的定性评估，不建评测流水线。​
- **历史增量缓存**——只缓存稳定前缀（工具定义 + 稳定系统模块），不对对话历史另打缓存断点。​
- **缓存 TTL / 断点数配置化**——TTL 用默认值、断点位置内置，本章不通过配置调整。​
- **状态栏展示缓存命中**——缓存信息只走 smoke / 调试输出，不进 TUI 状态栏。​
- **提示词运行时热加载 / 外部模板文件**——模块内容内置于代码，不做外部模板。​
- **多模态、流式工具结果**——沿用 ch04，不做。​

## 验收标准​
​
- AC1: 模块化装配——系统提示由按优先级排列的固定模块拼成，模块间以空行分隔；新增一个模块只需挂载、不改装配逻辑。(F1)​
- AC2: 可选空槽——「自定义指令/已激活 Skill/长期记忆」内容为空时装配自动跳过、不留多余空行；架构支持后续填充。(F1)​
- AC3: 环境信息呈现——系统提示第二段含工作目录、平台、当前日期、git 状态、应用版本、当前模型；与稳定模块分属不同内容块。(F2)​
- AC4: 缓存命中（Anthropic）——首轮 `cache_creation_input_tokens > 0`、次轮 `cache_read_input_tokens > 0`（稳定前缀命中）；仅环境信息/历史变化时稳定前缀仍命中。(F3/N1)​
- AC5: 缓存确定性——两次构造的稳定块逐字节相等；故意改变环境信息不改变稳定块内容。(F3/N1)​
- AC6: 缓存字段解析——provider 用量对外暴露缓存写/读；OpenAI 解析 `cached_tokens`，端点不返回时为 0 且不报错。(F4/N6)​
- AC7: 双重强化——关键约定（优先用专用工具、编辑前必先读）在**工具描述**与**系统提示模块**文本中均出现。(F5)​
- AC8: 补充消息注入——注入消息以 `<system-reminder>` 标签包裹，模型不把它当用户提问来复述/回应；该消息**不写入持久对话历史**。(F6/N3)​
- AC9: 规划模式按轮次注入——`/plan` 后：首轮注入完整提醒、之后每隔固定轮次重复完整、其余轮次注入精简版；规划模式仅放开只读工具；`/do` 切回全工具并按上文计划执行。(F7)​
- AC10: 跨协议一致——anthropic 与 openai（含兼容 base_url）都装配同一系统提示 + 环境信息、注入同一 reminder、都尽力缓存（anthropic 看缓存命中、openai 看 `cached_tokens`），行为一致。(F8)​
- AC11: 不破坏 ch04——ch04 关键行为（多轮连环、用户取消、历史一致、流出错恢复）仍成立；`pytest` 通过。(N2)​
- AC12: 历史合法——注入 reminder 后请求不返回 400；规划模式多轮 + 中途取消后再发一条仍可继续（历史配对合法）。(N3)​
- AC13: 环境采集降级——在非 git 目录或 git 不可用时，环境段对应项降级（留空/省略），界面不卡、请求正常发起。(N4)​
- AC14: 代码规范——`ruff format --check .` 通过、`ruff check .` 无告警；对话区与输出无 api_key 明文。(N5/N7)
