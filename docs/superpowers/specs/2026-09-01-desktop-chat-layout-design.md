# AlinCode 桌面聊天布局设计

## 背景

桌面端的聊天能力已经可用，但正式界面仍偏向终端展示，与已经确认的登录、聊天和设置原型不一致。用户要求借鉴 Codex 的信息分布：左侧导航、中间对话、右侧上下文；同时保留 AlinCode 已确认的深海蓝配色和透明 A 标识。

## 目标

- 将正式聊天页重排为稳定的三栏桌面工作区。
- 让已实现的聊天、历史、设置、模型、目录与本地额度获得清晰入口和可读展示。
- 不改变本地 Profile、WebSocket、Agent、命令行或桌面启动行为。

## 设计范围

### 布局

- 左栏固定展示 AlinCode 品牌、新建对话、当前 Profile 的对话历史和 Profile 摘要。
- 中栏是唯一的消息与输入主区域，顶部显示当前会话名称和设置入口。
- 右栏固定展示当前会话可读取的环境信息：连接状态、模型、协议、项目目录、本地 token 用量和预算状态。
- 窄窗口下优先保留聊天区；环境栏可收起，历史栏保持可访问。

### 视觉语言

- 使用现有透明 A Logo，不在 Logo 中新增角色或白色底板。
- 使用深海蓝底色、青蓝高亮和柔和分割线；不复制 Codex 的黑灰配色、文字或图标资产。
- 聊天正文使用易读的中文界面字体；代码与额度数据使用等宽字体。
- 用户消息使用低饱和蓝色气泡，助手消息保持无气泡阅读面；工具事件为紧凑状态卡片。

### 行为边界

- 「新建对话」、历史切换、设置入口、发送消息和已有的会话状态继续使用现有实现。
- 环境栏只消费已有的 Profile、Provider、工作目录与 usage 数据；缺失数据使用明确的空状态，不伪造数据。
- 不新增 Pull Request、插件、分享、Git 分支操作、云端同步、团队空间或其他尚未实现的入口。

## 组件边界

| 区域 | 职责 | 依赖的数据 |
|---|---|---|
| 左侧导航 | 创建和选择当前 Profile 的会话 | Profile、会话列表、当前会话 |
| 对话主区 | 展示消息、工具状态和输入框 | 当前会话、流式事件、连接状态 |
| 环境栏 | 只读汇总本次对话的本地环境 | Provider、模型、工作目录、usage、预算 |
| 设置弹窗 | 编辑已有 Provider、目录、预算配置 | 既有设置 API |

## 数据流

1. 页面加载后恢复当前 Profile 与会话历史。
2. 左栏选择或创建会话，主区订阅该会话的现有 Agent 事件流。
3. 现有 Profile 设置和 usage 更新后，同时刷新顶部状态与右侧环境栏。
4. 设置保存成功后，右侧环境栏显示最新的模型、目录与预算摘要。

## 错误与空状态

- 未连接时，环境栏显示「未连接」及下一步提示，不显示虚构模型或目录。
- 未配置模型时，主区引导用户打开设置；发送入口保持现有的阻止或报错逻辑。
- 历史为空时，左栏显示新建对话引导。
- 额度未设上限时，环境栏明确显示「未设置上限」，不显示百分比进度。

## 验收标准

- 在 Windows 桌面窗口中，聊天页呈现左侧导航、中间聊天、右侧环境三栏，且中栏占最大可用宽度。
- 所有已实现入口仍可用：新建会话、切换历史、打开设置、发送消息。
- 右侧仅显示当前 Profile 的模型、目录、用量和预算信息，不出现其他 Profile 的数据。
- 无模型、无目录、无预算或断开连接时，界面给出可理解的真实状态。
- 页面沿用深海蓝配色和透明 A Logo，不出现白色 Logo 背板，也不引入 Codex 品牌元素。
- 现有前端构建与后端自动化测试通过；桌面端可打开新布局并完成一次真实消息发送。

## 明确不做

- 不增加任何没有后端能力支撑的导航项或状态面板。
- 不重写聊天协议、Profile 存储、Provider 配置、Agent 工具执行或 TUI。
- 不在本次实现中加入响应式移动端、主题切换、拖拽栏宽、动画系统或全新图标库。
