# Agent 工作流可视化设计

## 目标

在对话消息流内，以可折叠卡片展示一次回答中的可见执行轨迹：处理状态、工具调用、结果和浏览器侧耗时。

## 范围与边界

- 复用现有 WebSocket 的 `tool.start`、`tool.end` 与 `turn.done` 事件，不改 Agent、Provider 或持久化格式。
- 不展示模型原始思维链；“正在分析”仅表示本轮正在执行，避免伪造或暴露不可审计的推理内容。
- 连续工具块在消息流中合为一张工作流卡片；助手文本仍按原顺序显示。
- 历史回放显示工具轨迹，但因为旧 JSONL 没有毫秒时间戳，不补造耗时。

## 交互与状态

- 卡片默认展开，标题展示“执行中 / 已完成 N 个步骤”、摘要与总耗时；点击标题可收起或展开。
- 每个步骤显示工具名、参数摘要、成功/失败结果、单步耗时；运行中步骤显示动态状态。
- 前端在收到 `tool.start` 时记录本地时间戳，在 `tool.end` 时计算耗时。总耗时从第一项开始至最后一项结束。
- 无工具调用的普通回复保持现有显示，不插入空卡片。

## 测试

- Reducer 测试：工具开始/结束会保存可见耗时，结束时间不早于开始时间。
- 组件测试：相邻工具块被合并为一个工作流卡片，并保留助手文字与工具结果。
