# Windows 本地桌面 Coding Agent Checklist

> 每一项必须通过实际运行、观察或测试结果验证；不得以阅读代码替代验证。

## 原型审批

- [x] 启动/Profile 原型已展示，用户确认首次创建、Profile 切换、密码解锁和隐私文案。（验证：用户明确回复确认。）
- [x] 聊天/历史原型已展示，用户确认三栏布局、工具/审批状态、取消操作与窄窗口行为。（验证：用户明确回复确认。）
- [x] 设置/额度原型已展示，用户确认 Provider、脱敏 API Key、项目目录、用量/预算布局和“非供应商余额”文案。（验证：用户明确回复确认。）
- [x] 上述三类原型全部确认后才开始正式 `webui/src` 页面实现。（验证：原型确认记录早于正式 UI 提交/修改记录。）

## Profile 与本机密钥

- [ ] 首次启动可创建本机 Profile，之后可选择并使用正确密码解锁。（验证：创建 Profile 后重启应用，错误密码失败、正确密码进入主页。）
- [ ] 同一 Windows 用户下可创建至少两个 Profile。（验证：创建 A、B 并分别解锁。）
- [ ] Profile A 与 B 的模型设置、历史、token 用量和预算不交叉。（验证：分别配置、对话和切换，观察数据独立。）
- [ ] API Key 在设置界面、REST 响应、浏览器 localStorage 和 Profile JSON 中均不以明文出现。（验证：保存已知测试 Key 后检查界面、响应、localStorage 和磁盘文件。）
- [ ] 已保存 API Key 可在重启后供当前 Windows 用户继续使用。（验证：重启、解锁并发起一次真实模型请求。）
- [ ] 非 Windows 平台的 DPAPI 调用以可理解错误失败，而不会静默改为明文存储。（验证：平台分支单元测试通过。）

## 工作目录、会话与 Agent 行为

- [ ] 用户只能在设置中选择存在的本地目录作为项目工作目录。（验证：选择文件或不存在路径时显示错误；选择目录成功后显示绝对路径。）
- [ ] 未选择工作目录时，工具型请求不会回退到应用安装目录执行。（验证：发送文件读取请求，观察明确阻止提示且无工具调用。）
- [ ] 选择项目目录后，真实 Coding Agent 请求可显示流式文本、工具执行、权限审批和最终结果。（验证：请求“读取并总结 README.md”，观察完整事件流。）
- [ ] 用户可取消运行中的轮次，界面恢复可发送状态。（验证：发起长任务后点击取消，观察轮次停止并可再次发送。）
- [ ] 新建、恢复和切换的会话只来自当前 Profile 的存储目录。（验证：A、B 各创建会话，切换后侧栏和恢复 API 均只显示当前 Profile 会话。）
- [ ] TUI 仍使用既有工作目录与会话行为。（验证：终端运行 `python -m Alincode` 并完成一次真实对话。）
- [ ] 本机浏览器调试入口仍可用。（验证：运行 `python -m Alincode --web`，访问本机地址并完成连接。）

## 用量与预算

- [ ] 每次收到模型 usage 后，当前 Profile 的输入/输出 token 统计正确累计。（验证：完成两轮已知 usage 的测试对话，比较前后数值。）
- [ ] 界面只称其为本地统计用量，不称为供应商账户余额。（验证：检查状态栏和设置页文案。）
- [ ] 预算为零时不限制发送；配置正预算并达到后，新轮次被明确阻止或需要用户确认。（验证：分别设置两种预算并发送请求。）
- [ ] Profile 切换后显示该 Profile 自己的用量与预算。（验证：A、B 设置不同预算和用量后切换观察。）

## 桌面运行与本机安全

- [ ] `python -m Alincode --desktop` 启动原生桌面窗口，不要求用户先打开浏览器或终端。（验证：开发机运行命令并看到窗口。）
- [ ] 桌面服务仅监听 `127.0.0.1`，端口由系统分配或未公开固定端口。（验证：检查监听地址和启动日志。）
- [x] 直接使用无效或缺失启动令牌访问桌面 Profile API/WS 会被拒绝。（验证：自动化集成测试通过。）
- [ ] 关闭桌面窗口后，本机 Web 服务和相关资源释放。（验证：关闭窗口后健康检查不可访问、端口不再监听。）
- [ ] 默认 TUI、`--web` 和 `--desktop` 三种入口互不改变参数语义。（验证：对三种命令进行启动冒烟测试。）

## 构建与发布

- [ ] 后端测试全部通过。（验证：`uv run pytest tests -q` 退出码为 0。）
- [ ] 前端构建成功。（验证：`cd webui; npm run build` 退出码为 0，生成 `webui/dist`。）
- [ ] Windows 构建脚本生成 `AlinCode-windows-x64.zip`。（验证：运行 `powershell -ExecutionPolicy Bypass -File scripts/build_windows.ps1` 并检查产物。）
- [ ] 在未安装 Python/Node.js 的 Windows x64 测试环境中，解压后双击可启动桌面应用。（验证：测试机完成启动并进入 Profile 页。）
- [ ] 便携包可完成创建 Profile、配置自己的 API、选择项目目录和一次真实对话。（验证：测试机逐项完成并记录结果。）
- [ ] README 说明 TUI、Web 调试、桌面包、本机数据位置、未签名 SmartScreen 风险和不支持跨设备同步。（验证：人工审阅 README 对应章节。）

## 端到端场景

- [ ] 场景 1：新用户首次启动桌面包 → 创建 Profile → 配置兼容 API → 选择项目目录 → 发送“读取并总结 README.md” → 观察流式回复、工具调用和完成状态。（验证：全链路实际运行。）
- [ ] 场景 2：同机创建第二个 Profile → 使用不同模型或预算 → 发送对话 → 切回第一个 Profile；两个侧栏历史、设置和用量均保持隔离。（验证：全链路实际运行。）
- [ ] 场景 3：Profile 已达到预算 → 发送新请求 → 得到明确的预算提示且 Agent 不执行；提高预算后重试成功。（验证：观察阻止与恢复行为。）
- [ ] 场景 4：运行原终端入口 → 发送真实请求 → 工具和最终回复正常；验证桌面改造未破坏 CLI。（验证：tmux 中完成一轮真实对话。）
